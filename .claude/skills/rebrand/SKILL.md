# Rebrand Tideline

Read `AGENTS.md` first. In the marketplace repository, a palette, typeface,
surface, state or mode change runs the design pass and colour pass before
markup. Record the new role table and computed ratios; a visual guess is not a
contrast check.

File paths below are relative to the Tideline project root. In the marketplace
repository, run file-level commands after `cd themes/tideline`; run the final
repository gates from the marketplace root.

## 1. Change the name and facts

Keep the filename `src/fixtures/marram.ts` unless you also update every import.
Change `HOUSE`, `ROOMS`, `MATERIALS`, `UPDATES` and `FAQ` there. `derive()` must
remain the only place totals are computed, and `materialFor()` must keep its
build-time throw.

The brand name reaches the React header and footer through the one
`data-brand-name` span in `src/components/ui/primitives.tsx`. Change
`HOUSE.name`, then search the prose and email renderer for literal uses:

```sh
rg -n "Marram|MARRAM" src html/src/data/marram.json
```

The uppercase wordmark in `src/emails/render-html.ts` is literal because email
HTML is rendered outside React. Update it too.

`html/src/data/marram.json` is a checked-in projection, not generated by
`build-html`. Mirror the changed house, rooms, materials, updates, FAQ, derived
values, emails and email chrome there in the same change. Keep the filename or
also update `html/html.json` `data`.

## 2. Edit the real token table

`src/theme.css` has these two mode surfaces:

- `:root, .tt-tideline, .dark, .tt-tideline.dark`: the complete 86-token
  default and dark table
- `.light, .tt-tideline.light`: 55 overrides; the remaining 31 values inherit
  because they are identical in both modes

Do not rename a token. Rebrand these families together:

| Family | Tokens |
|---|---|
| grounds and ink | `--background`, `--foreground`, `--card*`, `--surface-*`, `--muted*` |
| brand and state ramps | `--primary*`, `--accent*`, `--secondary*` |
| controls | `--border`, `--hairline`, `--ring`, `--field*`, `--control-border`, `--selection*` |
| semantic status | `--positive*`, `--warning*`, `--critical*`, `--info*` |
| signature | the five `--material-*` tokens |
| photographs | `--scrim` and the three `--plate-ink*` tokens |
| shape, type and motion | `--radius*`, `--font-*`, both type ladders, tracking, easing and durations |

Three Tideline rules stay true after a rebrand:

1. `--primary` may be a light-mode fill only when it misses the 3:1 graphic
   tier. Derive `--primary-ink` for links, rules, marks and small labels.
2. `--primary-hover` and `--primary-active` move in the direction that raises
   contrast against `--primary-foreground`. Tideline's shipped ramps lighten
   in both modes.
3. The photographs stay dark in both modes, so `--plate-ink`,
   `--plate-ink-muted` and `--plate-ink-brass` remain non-inverting unless the
   rebrand replaces the imagery and records a new mode decision.

## 3. Mirror the manifest and email colours

After editing CSS, update all three manifest surfaces:

- `theme.json` `tokens`: the resolved light table, all 86 keys
- `theme.json` `tokensDark`: the resolved dark table, all 86 keys
- `theme.json` `palette`: background, card, primary, foreground and border

Update `design.typefaces` if a family changes and bump the patch version for a
rebrand. Do not change `priceCents` or `license`.

Email clients do not reliably resolve CSS variables. Update the dark-mode `C`
map in `src/emails/render-html.ts`; every literal is labelled with its source
token. The HTML site CSS imports `src/theme.css`, so it needs no duplicate
palette edit, only a rebuild.

## 4. Compute AA for both modes

Run this after mirroring `theme.json`. It works from the repository root or the
downloaded project and exits nonzero when a required pair fails:

```sh
bun - <<'JS'
import { existsSync } from "node:fs";
const path = existsSync("theme.json") ? "theme.json" : "themes/tideline/theme.json";
const manifest = await Bun.file(path).json();
const linear = (value) => value <= 0.04045 ? value / 12.92 : ((value + 0.055) / 1.055) ** 2.4;
const luminance = (hex) => {
  const rgb = [1, 3, 5].map((i) => linear(parseInt(hex.slice(i, i + 2), 16) / 255));
  return 0.2126 * rgb[0] + 0.7152 * rgb[1] + 0.0722 * rgb[2];
};
const ratio = (a, b) => {
  const x = luminance(a), y = luminance(b);
  return (Math.max(x, y) + 0.05) / (Math.min(x, y) + 0.05);
};
const text = [
  ["foreground", "background"], ["foreground", "card"],
  ["foreground", "surface-raised"], ["foreground", "surface-sunken"],
  ["muted-foreground", "background"], ["muted-foreground", "card"],
  ["muted-foreground", "muted"], ["primary-foreground", "primary"],
  ["primary-foreground", "primary-hover"], ["primary-foreground", "primary-active"],
  ["primary-ink", "background"], ["primary-ink", "card"],
  ["accent-foreground", "accent"], ["secondary-foreground", "secondary"],
  ["foreground", "field"], ["selection-foreground", "selection"],
  ["positive-foreground", "positive"], ["warning-foreground", "warning"],
  ["critical-foreground", "critical"], ["info-foreground", "info"],
];
const graphics = [
  ["ring", "background"], ["ring", "card"], ["ring", "field"],
  ["control-border", "background"], ["control-border", "field"],
];
let failed = 0;
for (const [mode, tokens] of [["light", manifest.tokens], ["dark", manifest.tokensDark]]) {
  for (const [foreground, background, minimum] of [
    ...text.map(([a, b]) => [a, b, 4.5]),
    ...graphics.map(([a, b]) => [a, b, 3]),
  ]) {
    const value = ratio(tokens[`--${foreground}`], tokens[`--${background}`]);
    const ok = value >= minimum;
    if (!ok) failed += 1;
    console.log(`${ok ? "PASS" : "FAIL"} ${mode.padEnd(5)} ${foreground} / ${background}: ${value.toFixed(2)}:1`);
  }
}
process.exit(failed ? 1 : 0);
JS
```

The script checks token pairs. It cannot prove text over photography. Measure
the darkest, mean and brightest pixels behind any overlaid text after replacing
an image or scrim, then record those ratios. The shipped hero receipt is
17.11:1, 15.12:1 and 8.98:1 for `--plate-ink`; the land-gallery caption floor is
15.8:1 for plate ink and 9.8:1 for plate brass.

## 5. Replace the 23 images

All prompts and crop roles are in `src/assets/README.md`: seven images in the
first shoot and sixteen in the second. Keep one photographic register, one
light direction and one colour story. Replace every imported file at its real
intrinsic size or update the consuming component deliberately.

`tl-key.png` and `tl-layer-dune.png` are chroma-keyed transparent assets. Keep
their alpha channel, despill the keyed colour and leave contact shadow and
compositing in CSS.

An imagery change is not proven by the source check. Run the fresh registry
install because the registry projects binary imports to text stand-ins.

## 6. Swap fonts

Replace the woff2 files and OFL texts in `src/fonts/`, update `src/fonts.ts`, the
four `--font-*` tokens and `theme.json` `design.typefaces`. The HTML edition
copies the same files. The email renderer deliberately keeps system stacks
because Outlook does not reliably load webfonts.

## 7. Rebuild and verify

From the marketplace repository:

```sh
bun run build-html tideline
bun run verify-theme tideline
```

For a scoped preflight:

```sh
bunx tsc --noEmit
bun lib/pipeline/check.ts
bun run check-registry tideline --fresh
```

In a downloaded project, run `bunx tsc --noEmit`, `bun run build`,
`bun run build:html`, then follow `check-quality` for both-mode captures and
interaction checks.
